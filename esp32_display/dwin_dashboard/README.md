# DWIN DMG12480C068 儀表（評估中）

把儀表改用 DWIN 智慧串口屏（1280×480，T5L2 / DGUS II）的評估與素材。
**背景圖與 14/13/22 設定檔已可產生，但位元組格式尚未與開發指南核對，也還沒上過實機。**

## 為什麼素材要用程式產生

DGUS 的畫面分成兩層：

- **背景圖**（靜態）—— 卡片框、色條、中文標籤、單位、錶盤刻度。
  這些永遠不變，全部畫進一張圖，以 **24 位元 BMP**（檔名 = 頁編號，`00.bmp`）
  放進 `DWIN_SET/`。原本以為要打包成 `.ICL`，看了原廠工具的產出才知道不用。
- **變數控制項**（動態）—— 數值由 MCU 透過 UART 寫入 VP，螢幕自己疊上去。
  位置、字級、顏色、數值範圍定義在 `14.BIN` 裡。

背景圖用 `tools/gen_background.py` 產生而不是在 Photoshop 手拉，是為了讓
美術素材也能進版控、能 diff、能重現。

```bash
python3 tools/gen_background.py <字型資料夾> [畫面高度]
# 高度預設 480（DMG12480C068）；給 400 則產生 DMG12400C074 的版本，
# 檔名會加上 _400 後綴。兩者同為 1280 寬，只縮放垂直座標與字級。
# 輸出 assets/background.png（要轉 ICL 的）
#     assets/preview.png（疊上範例數值，僅供評估版面）
```

字型只有產生 PNG 時需要，**螢幕端不需要任何字型檔**：中文全是靜態的
已畫進背景，動態值全是數字，用螢幕內建的 0# ASCII 字型即可。

字重與明度層次：

| 角色 | 字重 | 顏色 | 對黑底對比 |
|---|---|---|---|
| 中央數值（時速/轉速/增壓） | SemiBold | `#FFFFFF` | 21.0:1 |
| 卡片數值 | Medium | `#FFFFFF` | 21.0:1 |
| 中文標籤 | Medium | `#E2E8F0` | 17.0:1 |
| 單位與刻度 | Medium | `#B4BFCC` | 11.3:1 |

單位原先是 `#8B95A5`（6.9:1）且用 Regular 字重，在黑底上偏暗、
車上不好讀。改為提亮 + Medium + 把最小的幾個放大
（增壓刻度 15→17、BAR/K/% 20→22、卡片 % 與 °C 22→24）。

小字最吃字重，光提亮顏色效果有限。

Montserrat 與 Noto Sans TC 的官方發布是可變字型，取不到中間字重，
需以 fonttools 抽出 Medium：

```bash
pip install fonttools brotli
python3 -m fontTools.varLib.instancer Montserrat.ttf   wght=500 -o Montserrat-Medium.ttf
python3 -m fontTools.varLib.instancer NotoSansTC.ttf   wght=500 -o NotoSansTC-Medium.ttf
```

所需字型檔：`Montserrat.ttf`、`Montserrat-Medium.ttf`、
`Montserrat-SemiBold.ttf`、`NotoSansTC-Medium.ttf`。

## 設定檔產生器

```bash
python3 tools/gen_dgus_config.py <字型資料夾> [畫面高度]
# 輸出 dwin_set/14.BIN   顯示變數（19 個控制項，全在第 0 頁）
#     dwin_set/13.BIN   觸控（主畫面沒有觸控元件，內容是空白頁）
#     dwin_set/22.BIN   VP 開機初值（含下面說的 SP 描述區）
#     nx4_dwin_vp.h     ESP32 端的 VP 位址表
#     assets/preview_dgus.png   用 DGUS 的字格重畫一次版面

python3 tools/gen_dgus_config.py --dump                  把 14.BIN 反解成可讀文字
python3 tools/gen_dgus_config.py --patch-cfg <原廠 CFG>   開啟觸控上傳與 PWM 背光
```

座標不在這支程式裡重新定義，它 `import gen_background.py` 用同一組常數。
背景圖上的單位、冒號、斜線是靜態的，數值是螢幕疊上去的，兩份座標一旦分家
就會對不齊。

`preview.png` 是版面草圖（Montserrat 的字寬），`preview_dgus.png` 是拿產生出來的
`14.BIN` 重畫的——數字照 DGUS 的字格排（字寬 = 字級 ÷ 2，基線在字格 78% 處）。
**要檢查座標有沒有寫錯，看後者。**

### 格式驗證狀態

`14ShowFile.bin` 的容器與描述格式已用參考專案**逐位元組驗證**：

```bash
python3 tools/gen_dgus_config.py --selftest DWIN_400_org/DWIN_SET
# selftest: 14ShowFile.bin 與參考專案完全一致（16512 位元組）
```

改到 `SPEC` 區塊之後請重跑這行——它是這份格式的回歸測試。

剩下沒驗到的（程式跑完也會列出來）：**觸控格式**（參考專案裡沒存到）、
圖示描述 `0x16~0x19` 的 `00 00 00 3F`、0# 字庫的字級上限、前導 0 的行為、
`22_Config.bin` 那 4 個位元組在頭還是尾、`120.lib` 的意義、CFG 的位移。

### 檔案格式（`DWIN_400_org/` 參考專案實測）

`DWIN_400_org/` 是用 DGUS V7.650 排了三個控制項存出來的參考專案。格式已經
**逐位元組確認**——`gen_dgus_config.py --selftest DWIN_400_org/DWIN_SET`
會用同樣的三個控制項重建 `14ShowFile.bin`，目前與原廠檔案完全一致。

| 檔案 | 結構 |
|---|---|
| `14ShowFile.bin` | 16 位元組檔頭 `14 "DGUS_2" 10` + 4092 個頁項目 + 描述資料區 |
| 頁項目 | **1 位元組控制項數量 + 3 位元組檔案位移**（不是單純的指標）。空頁數量為 0、位移指向描述區結尾 |
| `13TouchFile.bin` | 空檔就是 `FF FF`。**觸控格式仍未知**——參考專案裡的觸控沒有被存進去 |
| `22_Config.bin` | `0x20000` = 整個 VP 空間（0x0000~0xFFFF）的映像 + 4 個位元組 |
| `00.bmp` | 1280×400、24 位元、未壓縮 —— 背景圖，不需要 ICL |
| `120.lib` | 104 位元組，用途未明，先照抄 |
| `DWprj.hmi` | 純文字：`SCREENDSIZE=1280X400`、`SPADDRESS=5000`、`VARCount=64` |

#### 描述（32 位元組，共用的前半段）

| 位移 | 長度 | 內容 |
|---|---|---|
| `0x00` | 1 | `0x5A` 固定 |
| `0x01` | 1 | 控制項類型（`0x10` 資料變數、`0x00` 圖示變數）|
| `0x02` | 2 | `*SP`，`0xFFFF` = 不使用 |
| `0x04` | 2 | SP 描述長度（字）：資料變數 13、圖示變數 10 |
| `0x06` | 2 | `*VP` |
| `0x08` | 2 | X |
| `0x0A` | 2 | Y |

**`SP+n` 對應描述的 `0x06+2n`**，所以顏色（`0x0C`）就是 `SP+3` ——紅字警示靠這個。

#### 資料變數（`0x10`）的後半段

| 位移 | 內容 |
|---|---|
| `0x0C` | 顏色 RGB565 |
| `0x0E` | 字庫編號 |
| `0x0F` | 字級 |
| `0x10` | 對齊：**左 = 0、右 = 1、置中 = 2** |
| `0x11` / `0x12` | 整數位數 / 小數位數 |
| `0x13` | 資料型別（0 = 2 位元組整數、1 = 4 位元組）|
| `0x14` 起 | 單位長度與單位字串（我們一律 0，單位畫在背景圖上）|

#### 圖示變數（`0x00`）的後半段

| 位移 | 內容 |
|---|---|
| `0x0C` / `0x0E` | V_Min / V_Max |
| `0x10` / `0x12` | Icon_Min / Icon_Max |
| `0x14` | ICL 編號（工具在沒選圖示庫時寫 `0xFF`）|
| `0x15` | 疊圖方式：0 = 透明、1 = 不透明 |
| `0x16`~`0x19` | 工具寫的是 `00 00 00 3F`，**意義不明**。它在 SP 描述長度（10 字，剛好到 `0x19`）之內，不是填充，所以照抄 |

原本猜的「每頁固定 0x800、`0x5AA5` 兩位元組魔數、類型佔兩位元組、SP 從 `0x08`
起算」全部是錯的；巧合的是**顏色仍然落在 `SP+3`**，紅字警示的作法不用改。

### 關於 `32.icl`

參考專案裡的 `32.icl` 是 `DGUS_3` 開頭的容器，裡面包的是一張 **JPEG**
（就是那張 1280×400 的背景）。檔頭看得出幾個欄位：`0x08` 是檔案長度減 8、
`0x14` 是寬 1280、`0x16` 是高 400。

**只有一張圖的樣本推不出多圖的索引格式**。如果要把 ICL 也搬到 Mac 上產生
（那樣整條流程就完全不需要 Windows），需要再兩個樣本：一個裝 2 張小圖、
一個裝 7 張，對照索引怎麼長就能定案。

### VP 位址

| VP | 內容 | 備註 |
|---|---|---|
| `0x2000` | 時速 | |
| `0x2001` | 轉速 | 同時驅動 EV 圖示（值 0 才顯示） |
| `0x2002` | 增壓 | BAR ×100，有號 |
| `0x2003` | 水溫 | |
| `0x2004` | Hev 電池 | % ×10 |
| `0x2005` | 油箱 | |
| `0x2006` | 道路速限 | |
| `0x2008` | 里程 | 32 位元，佔兩個字 |
| `0x200A`~`0x200D` | 胎壓 FL/FR/RL/RR | |
| `0x2010`~`0x2012` | 時 / 分 / 秒 | |
| `0x2013`~`0x2014` | 月 / 日 | |
| `0x2015` | 星期 | 0=週一 … 6=週日，對應 7 張圖示 |
| `0x1000`/`0x1010`/`0x1020`/`0x1030` | 時速 / 轉速 / 水溫 / 速限的變數描述區 | 顏色在 `SP+3` |

紅字警示（超速、水溫過高、測速照相）不是另做控制項，而是 ESP32 往 `SP+3`
寫一個 RGB565 顏色。這也是這幾個控制項要配 SP 描述區的原因。

### 時鐘為什麼沒有用螢幕的 RTC

下面「時鐘：DWIN 端可以自己走」那節說明了 RTC 顯示控制項的好處，但
`RTC Display` 的描述裡有一段格式定義，本機沒有開發指南無從確認，寫錯就是
一片亂碼。所以先用三個 Data Variable（時/分/秒）由 ESP32 每秒寫入，冒號畫在
背景圖上。等格式確認後可以換掉，換掉時背景圖不用動——冒號位置是一樣的。

日期也一樣拆成月、日兩個變數，斜線畫在背景。**星期是中文，Data Variable 顯示
不了**，做成 7 張圖示（`assets/icons/week_0..6.png`）由 Variable Icon 依 VP 值切換，
維持「螢幕端不需要字型檔」。

### 一個受字格影響的細節

DGUS 的 0# ASCII 是等寬點陣，字寬固定是字級的一半，跟 Montserrat 不同。
凡是「靜態符號要和動態數字排在一起」的地方（時鐘的 `:`、日期的 `/`），
背景圖都必須改用字格座標畫，不能用字寬去推——所以 `gen_background.py` 裡
多了 `CELL()` 與 `cell_text()`。

|---|---|
| `background.png` → `00.bmp` | **Mac**，`gen_background.py` + `gen_dgus_config.py` |
| `14ShowFile.bin` / `13TouchFile.bin` / `22_Config.bin` | **Mac**，`gen_dgus_config.py` |
| `T5LCFG.CFG` | **Mac**，以螢幕出廠那份為底改兩個位元 |

**背景圖不需要 ICL**——原廠工具產生的 `DWIN_SET` 裡，背景就是一張 `00.bmp`
（1280×400、24 位元、未壓縮）。ICL 只剩圖示還要用，而圖示只有 EV 和 7 張星期，
量很小；真的卡住的話，星期可以退回不顯示，EV 可以改用一塊純色蓋掉。

也就是說**改背景美術不再需要 Windows**，只有動到圖示時才需要。

## 機種比較：DMG12480C068 vs DMG12400C074

| | DMG12480C068_03WTC | DMG12400C074_03W |
|---|---|---|
| 尺寸 | 6.8 吋 | 7.4 吋 |
| 解析度 | 1280 × 480 | 1280 × 400 |
| 長寬比 | 2.67 : 1 | 3.20 : 1 |
| 可視區 | 159.6 × 59.2 mm | 178.6 × 55.8 mm |
| 像素密度 | 8.02 px/mm | 7.17 px/mm |
| **亮度** | **250 nit** | **650~700 nit** |
| 12V 電流（全亮） | 200 mA | 375 mA |
| 喇叭 | — | 內建 2W |
| 控制器 / Flash / 介面 / 溫度 | T5L2 / 16MB / TTL·RS232 / −20~70°C | 同左 |

對版面的影響：垂直空間 480 → 400 px（−17%），等比縮放後時速由 230 px
變 192 px。因為 7.4 吋的像素較大，實際物理高度只從 28.7 mm 降到
26.8 mm。**螢幕變大了，字反而略小**——可用垂直像素與實體高度都變少。

`tools/gen_background.py <字型> 400` 可直接產出 400 版的預覽對照。

## 中央區為什麼是垂直堆疊

先試過圓形錶盤與半橢圓拱形，兩種都不理想：

- **圓形**：在 8:3 的長條螢幕上被高度卡死，左右各留約 128px 黑邊
- **半橢圓拱形**：橫向比例對了，但弧線與兩側方正的卡片格格不入，
  而且時速數字放拱內會頂到刻度、放拱外又擠壓下方元素

最後回到**單純的垂直堆疊**：時速 → 轉速 → 增壓，由上而下。
沒有弧線與刻度之後，時速數字可以放到 **230px**（圓形版只有 120px），
版面語彙也跟兩側的卡片一致。

代價是**沒有了「目前速度佔上限多少」的視覺指示**——只剩數字。
如果之後想補回來，可以在時速數字下方加一條細的水平進度條，
比弧線更貼合長條螢幕。

## 數值與單位的對齊方式

`km/h`、`RPM` 這些單位是**靜態的**——它們畫在背景圖裡，位置固定不能動。
因此採取「**以標稱位數置中、單位固定**」的作法：

- 標稱位數：時速 **兩位**、轉速 **四位**（`NOMINAL_SPEED` / `NOMINAL_RPM`）
- 該位數下數字剛好置中於畫面中線 640，單位固定貼在它右側
- 位數變多時數字**往左長**（右緣固定），所以永遠不會壓到單位

實際落點：

| | 兩位/四位（標稱） | 其他位數 |
|---|---|---|
| 時速 | `75` 置中於 640 | `188` 中心 583、`0` 中心 700 |
| 轉速 | `1750` 置中於 640 | `6800` 中心 624、`780` 中心 654 |

非標稱位數時視覺重心會偏移，這是靜態單位的必然代價；用標稱位數當基準
是因為那是行駛中最常見的情況。

> 基準線由 `gen_background.py` 從標稱字串**自動算出**，不是寫死座標。
> 改字級或改標稱位數時，單位位置與 EV 圖示範圍都會跟著重算。

## 時鐘：DWIN 端可以自己走

時間顯示 `HH:MM:SS`。字級用 60px 而非 64px——最寬的 `00:00:00` 在 64px
下是 276px，而卡片可用寬度只有 278px，餘裕不足以吸收實機的字型渲染差異。

**T5L 內建 RTC**，而且 DGUS 有 `RTC Display (0x12_00)` 控制項可以直接
依格式顯示 RTC。所以實作時不必像 LVGL 版那樣在 MCU 端維護軟體時鐘：
手機端只要**偶爾校時一次**（寫 RTC 的系統變數），螢幕就會自己每秒跳動，
連 MCU 斷線都不影響。

這比現行 LVGL 版的作法（MCU 用 `lv_timer` 每秒自增、手機每筆推送校時）
乾淨得多。

## 轉速為 0 時顯示 EV

引擎熄火（HEV 純電行駛）時轉速那列改顯示綠色 `EV`。這在 DGUS 上不能
直接做，因為：

- 轉速數值是 **Data Variable**，只能顯示數字，不能顯示文字
- `RPM` 單位是**畫在背景圖裡的靜態文字**，沒辦法隱藏

作法是用一張**不透明的 EV 圖示把整列蓋掉**（數值與單位一起蓋）。
圖示底色與畫面背景同為純黑，蓋上去看不出接縫。

DGUS 端用 **Variable Icon (0x00)** 或 **Animation Icon (0x01)**，
VP 指向轉速值、`V_Min`/`V_Max` 都設為 `0` —— 依規格書
「Values greater than V_Max will show no Icons」，轉速一大於 0
圖示就自動消失，不需要 MCU 額外送控制指令。

圖示範圍由程式從轉速的最寬情況（`8888`）與單位寬度自動推算，
目前為 **x 491..844、y 245..335**。

> 轉速字級改動時，**EV 圖示的尺寸必須跟著重算**——蓋不住就會露出底下
> 的數字或單位。`gen_background.py` 末尾的檢查會列出各位數的實際佔用
> 範圍與圖示涵蓋結果。

## 卡片內容的邊距

各卡片內容與卡片邊界的實際距離（以文字 bbox 計，非錨點）：

| 卡片 | 上緣餘 | 下緣餘 |
|---|---|---|
| Hev電池 / 水溫 / 道路速限 | 65 | 27 |
| 時鐘 | 72 | 28 |
| 胎壓 | 17 | 14 |
| 里程 | 32 | — |
| 油箱 | — | 18 |

胎壓是唯一「兩列」的卡片，原本第二列數字底部距卡片下緣只剩 **2px**，
看起來像壓到卡面。列距由 52 改為 44 並整組上移後改善為 14px。

> 調整字級或列距時記得重算 —— PIL 的 `la` 錨點是 ascender 線，
> 不是字的視覺頂端，用錨點估邊距會低估實際佔用高度。

## 版面草圖的已知取捨

- 高度只有 480（現行 1024×600 是 600），垂直空間相當吃緊
- 中央內容 y 41..451，左右卡片 y 12..468，中央比卡片略內縮
- 連線資訊（IP）已從主畫面移除。DGUS 原生支援分頁，那類東西應該
  放設定頁，主畫面最多留一個連線指示點

## 尺寸與座標

版面常數集中在 `gen_background.py` 上方，之後產生 `14.BIN` 時會共用同一組
座標，避免背景圖與變數控制項對不齊。
