# DWIN DMG12480C068 儀表（評估中）

把儀表改用 DWIN 智慧串口屏（1280×480，T5L2 / DGUS II）的評估與素材。
**目前只有版面草圖，尚未實作。**

## 為什麼素材要用程式產生

DGUS 的畫面分成兩層：

- **背景圖**（靜態）—— 卡片框、色條、中文標籤、單位、錶盤刻度。
  這些永遠不變，全部畫進一張圖，打包成 `.ICL` 下載到螢幕。
- **變數控制項**（動態）—— 數值由 MCU 透過 UART 寫入 VP，螢幕自己疊上去。
  位置、字級、顏色、數值範圍定義在 `14.BIN` 裡。

背景圖用 `tools/gen_background.py` 產生而不是在 Photoshop 手拉，是為了讓
美術素材也能進版控、能 diff、能重現。

```bash
python3 tools/gen_background.py <字型資料夾>
# 輸出 assets/background.png（要轉 ICL 的）
#     assets/preview.png（疊上範例數值，僅供評估版面）
```

字型只有產生 PNG 時需要（Montserrat / Noto Sans TC），**螢幕端不需要任何
字型檔**：中文全是靜態的已畫進背景，動態值全是數字，用螢幕內建的 0# ASCII
字型即可。

## 目前的分工預期

| 產出 | 在哪裡做 |
|---|---|
| `background.png` / 圖示 PNG | **Mac**，`gen_background.py` |
| `14.BIN`（顯示控制項）、`13.BIN`（觸控）、`CFG` | **Mac**，位元組格式在開發指南 §6/§7 有完整定義 |
| `*.ICL`（把 PNG 打包） | **Windows/Wine**，格式未公開，只能用 DWIN 的 ICL Tool |

分界線的意義：**移動數值位置、改顏色、改門檻只動 `14.BIN`，純 Mac 作業**；
只有改背景美術時才需要跑一次 ICL 轉換。

## 中央區為什麼是垂直堆疊

先試過圓形錶盤與半橢圓拱形，兩種都不理想：

- **圓形**：在 8:3 的長條螢幕上被高度卡死，左右各留約 128px 黑邊
- **半橢圓拱形**：橫向比例對了，但弧線與兩側方正的卡片格格不入，
  而且時速數字放拱內會頂到刻度、放拱外又擠壓下方元素

最後回到**單純的垂直堆疊**：時速 → 轉速 → 增壓，由上而下。
沒有弧線與刻度之後，時速數字可以放到 **230px**（圓形版只有 120px），
版面語彙也跟兩側的卡片一致。

代價是**沒有了「目前速度佔上限多少」的視覺指示**——只剩數字。
如果之後想補回來，可以在時速數字下方加一條細的水平進度條，
比弧線更貼合長條螢幕。

## 版面草圖的已知取捨

- 高度只有 480（現行 1024×600 是 600），垂直空間相當吃緊
- 中央內容 y 41..451，左右卡片 y 12..468，中央比卡片略內縮
- 連線資訊（IP）已從主畫面移除。DGUS 原生支援分頁，那類東西應該
  放設定頁，主畫面最多留一個連線指示點

## 尺寸與座標

版面常數集中在 `gen_background.py` 上方，之後產生 `14.BIN` 時會共用同一組
座標，避免背景圖與變數控制項對不齊。
